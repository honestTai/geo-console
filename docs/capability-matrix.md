# 统一 GEO 产品能力矩阵

本产品不是某一个上游项目的换皮，也不把多套后台并排部署。所有能力围绕同一个客户项目、同一组冻结问题、同一份不可变证据和同一条整改复测链路工作。

## 必须整合的能力

| 产品模块 | 借鉴来源 | 统一后的实现 |
| --- | --- | --- |
| 多客户项目与人工确认 | Ansvisor、Elmo | 任意行业客户建档；可用 DeepSeek 自动分析或完全手工配置；监测范围版本化，旧报告不随新问题变化 |
| 真实消费端采集 | open-geo、OneGlanse | Playwright 使用用户自己的登录会话，当前支持 DeepSeek、Kimi；保存正文、来源、截图和页面实际展示的 Query Fan-out；失败不补数 |
| 持续监测与复测 | Elmo、Gego | 冻结问题、平台、地区、重复次数和采集版本；按批次跟踪趋势，只比较配置一致的样本 |
| 品牌与竞品分析 | Elmo、OneGlanse | 提及率、首位推荐率、平均位置、竞品共现、逐问题输赢和平台差异 |
| 引用与信源分析 | Elmo、OneGlanse | 保存引用 URL、文章标题和域名，区分官网、第三方和未引用，形成信源榜与内容机会 |
| 官网 GEO 技术审计 | GEO Optimizer、open-geo | HTTPS、robots、Sitemap、AI Bot、标题结构、Canonical、Schema、可引用事实和联系方式检查 |
| 证据化诊断 | open-geo、GEORank | 比较客户页、竞品页和 AI 引用页的已确认主题覆盖；结论同时关联证据 ID 与问题 ID；模型只能做可选增强 |
| 整改与内容生产 | Ansvisor、GEORank、GEOFlow | 诊断转任务，生成内容简报和待审核初稿，回填真实发布 URL 并重新抓取验收 |
| 客户报告 | open-geo、Elmo | 中文管理层摘要、平台指标、问题矩阵、信源与主题覆盖、官网审计、整改进度、前后变化和证据索引；支持 PDF、JSON、证据 CSV |
| 业务归因 | Ansvisor | 真实导入 GA4、Search Console、表单、电话和业务台账 CSV；去重保存，和 AI 指标并列而不自动声称因果 |
| 本机与服务器运维 | Elmo、Ansvisor、OneGlanse | 本机 PGlite，服务器 PostgreSQL + Docker + Caddy；平台内创建、查看与撤销 Collector 节点，Cookie 永不上传 |

## 明确不合并的部分

- 不保留上游营销站、订阅计费、白标套餐、云端遥测和海外支付代码。
- 不把模型 API 回答标成 ChatGPT、DeepSeek 或 Kimi 消费端真实页面回答。
- 不生成虚构客户、虚构回答、Seed 指标或无法追溯到证据的排名原因。
- 不承诺通过“投喂文章”获得固定排名；报告只说明真实采样变化和证据支持的差距。
- 不直接复制强依赖 Supabase、ClickHouse、MongoDB、etcd 的运行栈；只有在实际规模需要时才引入相应基础设施。

## 产品闭环

```text
客户建档与官网审计
  -> 竞品和高购买意图问题确认
  -> DeepSeek / Kimi 真实页面基线采集
  -> 品牌、竞品、引用、感知和逐问题分析
  -> 证据化诊断与内容机会
  -> 整改任务、内容审核、真实发布 URL 验收
  -> 同条件复测与中文客户报告
  -> GA4 / GSC / 表单 / 电话线索归因
```
