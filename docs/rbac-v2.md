# RBAC V2：统一授权内核

实现日期：2026-09-06。重构基准：`a8e8cd284ee016aaa280f58ad36eb4b6709e3abc`。

本说明描述本地实现，不代表 Demo 已升级。旧测试数据无需保留；迁移仍不删除采集原始证据，不自动恢复被撤销的机构授权。

## 1. 分层与事实源

| 层 | 事实源 | 职责 |
| --- | --- | --- |
| 纯授权语义 | `packages/authorization/src/index.ts` | Principal、Policy、Resource、Decision；AND/OR、客户隔离、委派边界、路由匹配 |
| 身份快照 | `apps/worker/src/authorization/principal.ts` | 单条 SQL 同时读取账号、角色、有效权限、原始配置权限和客户范围；凭据版本校验 |
| 策略读取 | `authorization/policies.ts` | 数据库策略、精确路径优先、同优先级冲突拒绝 |
| 资源解析 | `authorization/resources.ts` | 可信资源解析器注册表；项目、批次、报告、会话、成员、角色、文件归属 |
| 执行入口 | `authorization/index.ts` | HTTP、文件、领域动作和事务内授权；解释器复用同一计算入口 |
| 配置管理 | `authorization/configuration.ts` | 权限目录、策略版本、校验、审计、只读诊断 |
| 异步身份 | `authorization/execution.ts` | 工作台和草稿执行者绑定、逐工具检查、撤权检查 |
| 成员委派 | `member-access.ts`、`auth.ts` | 创建、停用、恢复、密码重置、可管理标记及分配候选 |

`rbac.ts` 只保留机构授权、角色、成员分配等配置服务和旧消费者所需的访问快照投影；旧 `authorizeDynamicRequest` 不再是运行时入口。`permission_routes` 仅作为旧迁移输入，不能继续向它登记新功能。

## 2. 权限计算

普通成员的有效权限：**启用的权限目录 ∩ 机构授权上限 ∩ 多角色权限并集**，并排除系统专用权限。客户范围是同一快照中的“全部客户”或显式 ID 集合，不从另一个并发查询补齐。页面/功能的父子关系由数据库 `permissions.parent_key` 表示，不再靠前端硬编码推断。

权限父子树用于组织和选择，不产生隐式后端授权；一个权限是否能调用接口，由策略条件明确规定。允许条件为：满足全部 `allOf`，并在 `anyOf` 非空时满足其中至少一项。无条件的普通策略不允许创建。

系统超管身份来自数据库的唯一 `is_super_admin`，不是可分配角色、传入布尔标记或空 user ID。超管仍受到活动机构、策略停用和业务机构封禁边界约束。系统管理入口是不可委派边界；内置系统管理策略不能停用，保留恢复机构/配置的入口。

默认拒绝包括：未认证、停用账号、封禁机构、未登记或停用策略、不满足权限、未知资源、跨机构/客户、错误会话创建者。资源不存在/跨范围按 404 隐藏；功能权限不足按 403。列表仍由领域仓储使用同一 Principal 的机构/客户范围过滤，不能只靠列表页面隐藏按钮。

## 3. 动态配置与扩展

超管界面：**机构管理 → 权限配置 → 授权引擎**。

- **权限目录**：创建权限、修改显示名称/分组/父页面、启用或停用。新权限不自动授予任何机构或角色。
- **授权策略**：分页/搜索 HTTP、证据文件、后台动作和工作台工具策略；支持 OR+AND 和显式停用。编辑携带 `version`，并发旧版本返回 409。
- **授权诊断**：输入当前机构用户 ID、方法、真实路径，只计算匹配策略、权限和资源范围及允许/拒绝原因，不执行被测接口。

配置 API（全部仅系统超管）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/rbac/configuration/policies` | 分页策略与资源解析器目录 |
| POST | `/api/rbac/configuration/policies` | 注册策略 |
| PUT | `/api/rbac/configuration/policies/:id` | 带版本更新策略 |
| PUT | `/api/rbac/configuration/permissions` | 新增/更新权限元数据与开关 |
| POST | `/api/rbac/configuration/explain` | 无副作用的授权诊断 |

策略键、方法、路径、资源绑定、范围及系统/创建者边界在创建后不可变。要改变结构，应注册新策略，不允许通过修改旧策略取消项目隔离。新增自定义策略不能与已有路由重叠，配置写入使用全局事务锁串行化；遗留重叠同优先级规则在执行时拒绝。权限键不删除、不重命名，以免悄悄改变历史角色语义；停用保留定义和审计。

新增功能步骤：

1. 在对应领域实现 API/工具，不能期望创建策略自动生成业务代码或页面。
2. 若现有解析器不足，在 `resources.ts` 增加有类型的可信解析器；禁止数据库配置任意 SQL、HTTP 或脚本。
3. 添加权限和策略（产品内置功能通过新的递增 migration；实例扩展可通过配置 API）。
4. 显式授予机构，再授予角色，分配用户和客户范围。
5. 新后台入口必须传 `ExecutionActor` 并使用共享授权；新工具未登记策略默认拒绝。
6. 用解释器检查正例、缺权限、跨客户、撤权和冲突；同步 Schema、文档和测试。

内置导航的 `navigation_key` 不可改成任意页面；新增菜单还需要实现受支持的 Web/Tauri 视图。权限管理不是任意代码插件平台。

## 4. 成员管理不能间接提权

同一 `decideDelegation` 同时控制分配候选、列表 `can_manage` 和写操作：

- 非超管不能授予自己没有的权限或客户；不能把受限范围变成全部客户。
- 对目标用户使用**配置权限**而不只是当前有效权限。机构上限暂时屏蔽的“休眠权限”也计算在内，防止后续恢复上限时出现潜在提权。
- 不能管理自己或系统超管，不能跨机构分配角色/客户。
- 显式 `roleIds: []` 就是无角色；省略时才按稳定 `roles.system_key` 查默认角色。新成员默认无客户范围。
- 角色定义与机构上限独立；撤销机构权限不删除角色定义。
- 生命周期操作在事务中锁定机构/目标账号后重验权限，并审计；重复邮箱/停用邮箱给出明确 409，不泄漏数据库错误。

## 5. 身份与并发

`users.credential_version` 由密码变化触发器递增；会话创建时绑定同一版本。登录先验证密码，再在机构/用户锁内重读账号和原始哈希，确认其没有变化才创建会话。因此“旧密码已验证 → 重置完成 → 旧请求插入新 token”不会留下有效会话。

每次认证校验会话有效期、撤销状态、账号状态、机构状态及凭据版本。自己改密码需要当前会话和旧密码验证，只升级并保留当前会话的版本；管理员重置/停用撤销该成员所有会话。恢复/解封不复活旧 token。

组织授权、角色、用户范围和状态触发 `authz_version` 更新。版本用于解释与前端身份更新，不缓存旧授权。高风险成员/审批写操作在和撤权相同的锁边界内重新授权；一般 HTTP 请求按接收时快照授权，不宣称已经发出的外部请求可以被撤回。

## 6. 异步任务和工作台工具

`agent_sessions.execution_actor` 与 `agent_runs.execution_actor` 显式记录 user / service / local / unassigned。

- HTTP 创建会话/草稿/报告/文章时传当前用户；会话内派生任务绑定会话执行者。
- Agent Worker 领取后、模型执行前、每个工具调用、回合结束和自动审批时重新检查。被停用、撤权、移出客户范围或来源会话取消后，不能继续调用受控工具或自动写入正式业务记录；授权失败直接终止，不消耗重试次数循环尝试。
- 服务端模型运行和桌面 Responses 代理有约一秒周期的撤权取消检查；外部请求已经发生的费用不能回滚，网络取消也不是外部服务已停止计费的保证。
- 工作台工具独立登记策略。例如 `create_batch` 需要 `workbench.run` + `monitor.run`，`run_site_audit` 需要 `workbench.run` + `audit.run`，`propose_questions`/确认范围需要 `project.onboard`，`advance_report` 需要 `report.generate`；不能只凭工作台入口权限绕过其他功能权限。
- 普通草稿自动审批需要 `workbench.run` + `agent.approve`，并检查会话未取消、开启自动模式且执行者一致。报告叙述和质检仍必须人工批准。文章自动物化只适用于文章 purpose。
- `report-scheduler` 是唯一内置 service actor，最高能力仅报告生成/报告及证据读取，并与机构上限相交，不具备人工审批或用户管理权限。
- `local` 仅在非 production 且数据库确实零用户时可用；`unassigned` 永不自动当成超管。登录会话退出/过期不等于取消用户已提交的持久任务；任务仍受当前账号、权限和范围检查约束。

## 7. 文件、封禁与迁移

`/artifacts` 必须同时通过文件类型功能策略和机构/项目范围；已知 URL 不是访问凭证。采集、网站、报告、语义解析响应分别配置策略。公开报告分享在机构封禁期间不可读取，解封后未过期且未撤销的链接可再次使用；分享记录和原始证据不删除。

封禁事务原子更新机构状态并撤销非超管会话；新的定时监测、采集领取和定时报告推进跳过封禁机构。已有采集证据保持不变，已经发出的采集请求仍可完成记录。

`0021_authorization_kernel.sql` 必须和 API、Agent、Web/Tauri 同步升级。迁移复制旧权限路由并折叠 OR 条件，补齐凭据/授权版本、权限父子关系、执行身份和新策略。已知创建者的旧会话/关联草稿可回填；无创建者的旧任务保持 unassigned，不能静默提权续跑。当前只在新建隔离 PGlite 上验证迁移，不自动操作现有 PostgreSQL。

浏览器本地验收使用 `GEO_DATA_DIR` 指向新临时目录、独立 API/Web 端口；`GEO_DEV_API_ORIGIN` 仅用于 Vite 开发代理隔离。Demo 未在本轮发布。
