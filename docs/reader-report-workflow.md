# 面向客户的诊断、证据与行动闭环

## 目标和计算边界

报告先回答“发现什么、依据是什么、谁改、怎么验收”，再展示公式与完整原文。展示说明使用“初步结果”“无法判断”等中文；内部 V2/MetricSnapshot/limited 契约保留，但不直接暴露给客户。原始回答中的术语不改写。

本任务基准：`680220703cd4659795deff922a2425decd71012d`。影响 architecture/domain/operations/capability；不增加模型平台、生产服务、自动发布或自动付费采样。代码实现不等于已部署。

`packages/metrics/src/communication.ts` 是 Web/PDF/Word 共用的释义、公式、限制和解释模型，仅消费同一冻结指标/config/Capture。正式算法仍以 `visibility.ts` 为准：先问题等权，再纳入的平台等权；次数用于核对，不直接池化多平台/不等重复次数计算总分。

- 采集覆盖 = 成功回答/计划采集；解析覆盖 = 可判断回答/成功回答；问题覆盖 = 达标问题/计划问题。它们是完成度，不是企业得分。
- 监测品牌份额仅以客户及已选竞品为分母，不是市场份额。逐题列出提及/所有监测品牌提及次数与对应证据。
- 点名与不点名分组依据冻结全名/已确认别名精确归类，不猜别名；按原纳入规则计算，是阅读辅助而非另一套排名。
- 搜索来源、明确最终引用、来源不可观察分别统计；引用 URL 条数不等于有引用的回答数。失败、未知、无官网和不可观察来源不补零。
- `getBatch` 在解析排队/运行期间不返回似乎已完成的解释；历史缺失说明明确披露，不回退旧排名。

## 新报告与证据

新冻结报告内部模板为 `zzgeo.report.v4`：范围与结论 → 问题/行动（保留批准任务、冻结同条件配对比较）→ 官网改法 → 文章用途/发布计划 → 公式和逐题明细 → 全文证据。快审、整改、复测保留各自边界；不重算总分差或声称优化因果。

新模板优先采用 `report.ts` 从该批次证据重新派生的 `analysis.gaps`，避免旧发现里的“搜索等于引用”和通用故障建议重复出现。批准叙述仍单独展示为建议/AI 评价，不把原话当事实鉴定。旧快照和已有 PDF/Word 不覆盖。

`report-evidence.ts` 在冻结前补齐叙述、发现、文章及嵌套渠道引用的同客户历史网页/搜索/审计正文；研究搜索不混入监测回答。引用缺失或越权返回 409，不能冻结无法复核的新报告，不抓实时网页填旧证据。

HTML/PDF 使用文内锚点，Word 使用原生书签/超链接；附录保留全文及分开的最终引用/搜索来源链接。外链仅 HTTP(S)，拒绝脚本、data 与带凭据 URL。官网原始文件仍由工作台按权限下载，报告呈现已保存的源摘录、URL、定位和截图。截图只读取该审计 PNG 并验证 SHA-256，缺失不挪用其他记录；新报告含 ZZGEO Logo、水印、冻结客户资料。导出全文属于敏感交付物，不放公开帮助页、运行日志或生产测试数据。

## 官网与文章

`website-language.ts` 提供每项检查的普通读者名称/含义/负责人，`website-guidance.ts` 提供定位/改法/验收。通过项明确无需重复改；无官网为不适用。代码/抓取规则问题不能只靠图片证明。

官网技术分数同时显示真实计分权重与公式：通过全部、警告一半、失败零，参考项不计分；这是原有审计算法的解释，不是新增 AI 排名。逐题客户名次显示明确推荐中位数，缺名次不再误写“未出现”；竞品只展示确实计算的提及率。业务导入汇总明确是同来源/指标求和，不假称自动采集或优化因果。

新 Agent 建议必须有 deliveryType、ownerRole、acceptanceCriteria；只有 content 可批量排队或直接启动文章工具。技术/采集/研究建议和未分类历史建议明确跳过或要求先重生成有分类的批准建议。

`agent-measurement-context.ts` 为 `read_project_context` 真正提供运行绑定的指标、冻结配置与 readerGuide（不只是提示词要求）。问题/竞品与文章问题 ID 校验采用冻结集合，当前客户资料单独披露；不拿最新解析替换运行绑定指标。原回答读取映射冻结问题/地区/语言，不改 Capture。

新文章必须绑定监测问题，并提交 PublicationPlan：用途、受众、实际缺口、具体平台/栏目、理由、调整方式、账号/授权/规则前置条件、验收步骤。渠道分为自有/证据中出现/候选待核验；证据中出现必须绑定证据，不能承诺已收录或排名。

文章生成使用 `geo-agent.v9-plain-language`：从目标建议、冻结问题、真实回答/来源和已有官网资料决定本次受众、内容类型、篇幅与结构，不默认采购者、不强制长文或 H2/列表/表格。v9 增加自然行文要求，避免泛化营销词和套用“先看结论”等标题。`publicationPlan.contentStrategy` 记录自由文本的 `format/rationale/lengthApproach`，新提交必须完整填写；不是固定类型枚举、段落模板或统一字数目标。`outline` 可为空/省略，正文只要求非空；60,000 字符上限与大纲项数上限是资源保护，不是写作任务。人工编辑也允许短内容，拒绝纯空白正文。资料不足仍列 `factGaps` 并保留待补充占位，不能借自适应篇幅编造事实。

Web 编辑/预览与新 PDF/Word 展示“为什么这样写”、形式理由和篇幅依据。新增说明保存在既有 JSON 发布计划内，无需额外 migration；历史草稿仍可读/批准，缺写作方案明确披露，不自动套模板补齐。重新生成走新校验，仍需用户主动触发，不自动发布或保证 AI 引用。

migration **0026** 加法增加可空 `optimization_articles.publication_plan` 与定位元数据策略，旧文章不填造假计划、不自动付费重写。新提交校验严格，历史批准记录可读；人工可补计划，也可重生成批准建议后生成新文章。

文章编辑保存计划/版本，发布校验与写入在行锁事务内；登记已发布必须有实际 HTTP(S) 地址、计划，正文无 `【待补充：…】`。计划不能注入文章未绑定的证据。登记地址不是自动发布/AI 引用证明。报告冻结文章计划、目标问题和地址，后续修改不影响旧报告；效果另行严格同条件复测。

## UI 和权限

`MetricLabel` 提供可键盘打开的释义，`MeasurementExplanation` 展示漏斗、实际分母、逐题纳入原因和原回答入口。`PublicationPlanView/Fields` 展示/编辑文章用途而非 dump JSON。

所有 EvidenceRef（含当前索引外历史 ID）先由全局 `/api/projects/:projectId/evidence-reference/:evidenceId` 定位真实 kind/batch。此接口只读元数据且限制当前机构/客户，不授予正文或文件权限；下游 API/artifacts 独立鉴权。权限不足/缺失明确提示，不能打开最新批次或其他记录替代。

## 验收、发布与排障

- 新建 PGlite 测试 0026、计划版本/发布拦截、历史引用冻结/跨客户拒绝；不连接推断出的外部数据库。指标夹具覆盖 50 计划/47 回答/44 可判断、2/3 份额、41 搜索回答与 1 个最终引用回答/5 条引用，数据仅在测试中。
- HTML/Word 测试完整原文、锚点/原生书签、危险 URL、PNG、旧快照兼容；桌面只读预览明确标记布局验收，不重新采样，不执行未要求的手机检查。
- 交付前 check-types/test/build/lint、major check-drift（上述基准）、workspace 依赖 license-check；内存数据库资源受限时限制 Turbo/Vitest 并发，不跳过断言。
- 发布需一致版本 API/Agent/Report/Web 与 0026。备份包含文章计划、冻结全文与对象文件；回滚应用不删新增字段/对象，新模板保留兼容 Report Worker，不能由旧 Worker 回填新快照。
- 旧报告没新布局不是故障，不覆盖对象；文章未分类先重新批准内容建议，不反复排队；引用 409/打不开需区分客户归属、文件缺失、正文/文件权限，不能放宽隔离修链接。
- 部署、付费重跑、重生成和审批须用户另行触发，本地通过不等于真实模型新输出或线上已验收。
